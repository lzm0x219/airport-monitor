# Airport Monitor 使用与数据说明

本文说明安装、日常操作、数据口径和故障恢复。[返回项目首页](../README.md)。当前源码版本为 1.0.1。应用沿用原内部 Bundle Identifier 和存储目录。

## 从发布版本安装或更新

1. 从 [GitHub Releases](https://github.com/lzm0x219/airport-monitor/releases) 下载 ZIP 并解压。
2. 如果已有 Airport Monitor，先退出正在运行的应用。在访达中将解压后的应用移动到「应用程序」文件夹；更新时请移动到旧版所在文件夹，并在提示时选择「替换」。关闭主窗口不会退出应用。
3. 从「应用程序」文件夹打开应用。默认发布包未使用 Apple Developer ID 签名，也未经过 Apple 公证，macOS 可能提示无法验证。如果已确认下载来源可信且文件未被篡改，仍选择打开，可在「系统设置 → 隐私与安全性」中选择「仍要打开」，再按系统提示完成验证和确认。详见 [Apple 的说明](https://support.apple.com/zh-cn/102445)。

如需核对下载，将发布附件中的 ZIP、`SHA256SUMS.txt` 和校验文件列出的其他附件放在同一目录，在该目录执行 `shasum -a 256 -c SHA256SUMS.txt`。

在一台 Apple Silicon Mac 上，从本地构建的 1.0.0 覆盖为下载版后，原有数据和设置保持一致，订阅仍显示已保存。跨版本自动更新已使用独立标识和空合成数据的测试版验证；正式发布版的跨版本升级、真实订阅读取、登录启动、系统重启后体验及 Intel 实机尚未验证。更新后钥匙串可能要求重新授权。具体范围见[验证记录](VALIDATION.md)。

## 应用内更新

支持应用内更新的版本默认定期检查已发布的稳定版；下载并验证更新后会提示重启，也可在设置的「关于」中稍后重启。选择稍后后，退出应用时也可能安装已下载的更新。可在「关于」关闭自动检查或手动检查更新。

检查更新会连接 GitHub 及其下载服务，不发送订阅链接。旧的 `v1.0.0` 下载包没有更新器，需要先按上面的步骤手动安装包含更新功能的新版本。请将应用复制到「应用程序」后从那里打开；直接从下载目录运行或处于系统隔离运行状态时，可能无法自动更新。如果设置中显示当前版本无法检查更新，也可通过 Release 页面手动更新。

## 运行

- 需要 macOS 14 或更新版本，以及返回 `subscription-userinfo` 响应头的 HTTPS 订阅。应用不接管代理，也不解析节点列表。
- 在主窗口点击「＋」，读取订阅、核对预览并填写机场名称。配置中可设置套餐名称、重置规则和机场提醒。
- 菜单栏可显示图标与余额、仅余额或仅图标；面板支持平面布局和分区卡片。显示方式、布局、单位和外观在设置中即时生效。
- 每个机场可独立暂停、移除和恢复。移除是归档：停止监测与提醒，但保留配置、订阅凭据和历史。主力机场决定菜单栏显示，不影响主窗口浏览其他机场。
- 左键打开菜单栏面板，右键提供同步、设置和退出。关闭主窗口不退出应用；重复打开会唤起已有窗口，面板已打开时保留面板。登录启动需在设置中开启。

更换同一机场的链接或令牌默认保留历史，新读数需要核对；选择「更换数据来源」才开始独立历史。已保存的链接不会回显，留空表示沿用。

## 用 Xcode 打开编译

建议使用 Xcode 26 或更新版本，打开 `AirportMonitor.xcodeproj`，选择共享 scheme **AirportMonitor** 和 **My Mac**，按 ⌘R。也可在项目根目录通过终端构建 Apple Silicon 与 Intel 的调试版本：

```sh
xcodebuild -project AirportMonitor.xcodeproj \
  -scheme AirportMonitor -configuration Debug \
  -derivedDataPath /tmp/AirportMonitorBuild \
  'ARCHS=arm64 x86_64' ONLY_ACTIVE_ARCH=NO build
```

产物位于 `/tmp/AirportMonitorBuild/Build/Products/Debug/Airport Monitor.app`。调试构建使用本机 ad-hoc 签名，未配置更新公钥时不会检查更新。默认发布构建同样采用 ad-hoc 签名，没有 Apple 公证；两者为加载更新框架关闭库验证。发布模式和更新密钥配置见[构建与发布](release.md)。重新签名或更改 Bundle Identifier 后，钥匙串可能要求重新授权。若 Documents 或 iCloud 目录触发 `resource fork ... not allowed` 签名错误，可使用上述 `/tmp` 构建目录。

运行核心逻辑、原生模型和模拟网络测试：

```sh
swift test --scratch-path /tmp/AirportMonitorTests
```

## 数据口径与边界

- 已用流量是服务端 `upload + download`；剩余为总额减已用，最低为零。默认显示十进制 GB，可切换 GiB；显示单位不改变原始读数或提醒阈值。
- 总额为零时显示总量未知，不推断余量或比例；到期值为零或缺失时显示未提供。真实零值与无数据分别显示。
- 重置按保存的规则及时区计算，支持每月固定日、按购买日或指定一次；短月按月末计算。界面显示设备本地时间，不从到期、套餐名称或计数回落推断重置，也不修改服务端计数。
- 订阅读数可能包含其他设备用量、服务商倍率和延迟，不是本机网卡用量或实时速度；最终以服务商账单为准。
- 同一订阅地址的请求至少间隔 72 小时，默认自动同步间隔为 72 小时，也可选 7 天。添加预览、手动同步和失败重试共用持久限频；请求开始后的失败或取消仍计入间隔。
- Mac 休眠或应用退出期间不采样。读数超过 30 分钟标为旧读数；失败时保留旧数据并显示错误，主窗口区分限频等待、可刷新和同步失败。

## 用量统计与预测

首次读取只建立基线。统计使用同一来源的可比较观测区间；跨日差额不分配到每天，缺记录不补零。完整落在筛选范围内的可比较跨日区间可计入期间总额。统计时区可在「同步与提醒」中设置，与每个机场的重置规则时区相互独立。

主窗口的采样后预测锚定最后一次成功读数与当时的重置规则，不随等待时间平移。至少需要 4 次可比较读数、覆盖 3 个统计日期，跨度达到 3 个采样间隔：72 小时间隔为 9 天，7 天间隔为 21 天。相邻间断超过 2 个采样间隔时断开，回看范围取 28 天或 6 个采样间隔中较长者。

跨重置、计数回退、总额、来源或规则变化后重新积累；未知余量、缺少有效重置、零增长或到期不晚于重置时不能给出有效预测。失败、暂停、待核对等情况下，已有估计会标为历史。预测仅供参考，参数尚未经长期真实数据验证。

预计不足提醒使用独立的连续预测资格，不由主窗口预测直接触发。细节见[统计与预测决策](adr/0004-observed-statistics-and-forecast.md)和[提醒决策](adr/0005-reminder-policy-and-delivery.md)。

## 提醒

开启系统通知并获得 macOS 授权后，可按机场选择低余量、预计不足和到期提醒。新机场的低余量阈值按总额百分比判断；旧版 GB 阈值保留，也可改用百分比。

提醒有持久去重和冷却规则。系统接受通知请求不代表用户一定看到横幅，资格与投递边界见[提醒决策](adr/0005-reminder-policy-and-delivery.md)。

## 隐私、存储与故障恢复

- 订阅链接保存在本机登录钥匙串，不写入偏好、历史或日志。机场配置、读数和提醒状态保存在本机；历史为明文，备份时请注意隐私。
- 订阅读取发往所填地址及其 HTTPS 重定向目标，最多跟随 5 次重定向，不降级到 HTTP。应用读取响应头后取消正文下载，不解析或保存节点；网络栈仍可能接收少量已在途正文。软件更新会连接 GitHub 及其下载服务，不发送订阅链接。没有分析服务、远程遥测或 iCloud 同步。
- 沙盒数据通常位于 `~/Library/Containers/local.SurgeTrafficMonitor/Data/Library/Application Support/SurgeTrafficMonitor/`。`native-v2/state.json` 保存目录、来源和历史，不保存订阅链接；全局显示、同步和通知偏好保存在 UserDefaults。
- 损坏或不兼容的历史不会静默覆盖，应用会暂停相关采样。设置的「数据与隐私」中可隔离损坏文件并重新开始，原文件保留为 `.corrupt` 副本；写盘失败时不会把未落盘的读数当成成功。
- 旧来源历史保留，归档不会删除钥匙串条目或注销远端订阅。当前不自动裁剪历史，也没有 CSV 导出；可在主窗口查看来源历史。

存储身份、原子提交与恢复边界见[存储决策](adr/0003-native-source-storage.md)。

## 设计预览

给应用可执行文件添加 `--design-demo --show-main` 可打开合成数据预览；`--panel-preview` 查看面板，`--light` 或 `--dark` 选择预览外观。预览不读取真实订阅或历史，不发送通知、不修改登录启动或保存机场配置；设置分类的切换仅在本次预览中生效，不会覆盖已保存的分类偏好。

## 常见问题

- **刚添加后不能立即刷新**：添加预览也是一次读取，同一地址的下一次请求需要等待 72 小时。界面会显示已知的最早刷新时间。
- **每日用量图有空白**：没有可归属到某一天的记录时，图表不会编造每日用量；完整落在统计范围内的可比较跨日区间仍可计入期间总量。
- **没有流量信息**：应用使用 `Clash/1.0` 客户端标识读取一次；若响应缺少 `subscription-userinfo`，请检查链接和服务商支持情况。HTTP、证书及格式错误会分别提示。
- **401、403 或证书错误**：检查链接是否失效、服务商访问规则和系统证书。应用不会忽略证书验证。
- **钥匙串无法读取**：解锁登录钥匙串并允许当前签名的应用访问；重新签名或更改 Bundle Identifier 后可能重新提示。
- **菜单栏看不到图标**：检查屏幕宽度、刘海和菜单栏管理工具，或在 Finder 重新打开应用。

`Sources/Core` 包含订阅读取、采样、统计、预测和持久化规则；`Sources/App` 包含原生界面、钥匙串和系统通知。`Tests` 使用隔离数据与模拟网络。构建和实机验证范围见[验证记录](VALIDATION.md)。
